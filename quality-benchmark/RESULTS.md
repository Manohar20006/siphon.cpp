# Codex vs MCP/Gemini Quality Benchmark

## Scope

Both implementations received the same nine-requirement specification for a
dependency-free task board. The Codex version was implemented directly; the
MCP version was generated by the Antigravity Gemini worker as a unified patch,
applied by the MCP, verified by the shared evaluator, and reviewed again by the
worker from captured test evidence.

## Results

| Check | Codex | MCP/Gemini |
|---|---:|---:|
| Shared static/structural evaluator | 11/11 | 11/11 |
| Add trimmed task | Pass | Pass |
| Complete task and update counts | Pass | Pass |
| Completed filter | Pass | Pass |
| Persist task and selected filter after reload | Pass | Pass |
| Clear completed and disable control | Pass | Pass |
| Semantic controls and live status | Pass | Pass |
| Dependency-free responsive implementation | Pass | Pass |

## Qualitative difference

Functional parity was achieved on this benchmark. The direct Codex version has
more distinctive visual design and somewhat more deliberate empty/error-state
presentation. The MCP/Gemini version is clean and accessible but visually more
generic. Therefore this run supports parity for correctness and core code
quality, not universal equivalence for visual taste or every future project.

## Conclusion

The MCP route met the same functional quality gate as the direct Codex route in
this controlled task. The verification loop is essential: worker output alone
is not accepted, and finalization occurs only after the shared evaluator and
browser behavior checks pass.
